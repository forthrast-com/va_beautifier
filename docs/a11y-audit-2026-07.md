# Accessibility audit — 2026-07-14

axe-core 4.x over the built site (light + dark, drawer open/closed, settings
open) plus a manual keyboard-flow probe, run via agent-browser against a local
`http.server`. Pages sampled: `index.html`, `laudato_si.html` (long modern,
section indicator), `gaudium_et_spes.html` (old flat). Reusable harness:
`scratch/axe_scan.sh` + `scratch/axe_runner.js` (axe.min.js borrowed from
`../mortolista/scratch/node_modules/axe-core/`).

## What already works

- `lang="en"` on the root; sane tab order; UA focus outlines intact.
- Drawer tab strip uses real `role="tab"` semantics; the drawer toggle
  carries `aria-expanded`; bookmark toggles have `aria-pressed` and
  descriptive labels ("Bookmark Preamble").
- No `<img>` content at all — hero art is CSS, so no alt-text exposure.

## Findings

### Serious — colour contrast (axe `color-contrast`, WCAG 1.4.3)

| Surface | Element | Colours | Ratio |
|---|---|---|---|
| reader, light | `.chapter-num` eyebrow (`h2`) | `#888` on `#faf9f7`, 14.4px bold | 3.36:1 (needs 4.5) |
| reader, both themes | `.para-num` gutter numbers | `#aaa` on `#faf9f7` | 2.2:1 |
| drawer, dark | inactive tab buttons + TOC links | `#8a8275` on `#1f2822` | 3.99:1 |
| index, both themes | `.brand`, `.sort-direction`, sort buttons (~10 nodes) | muted greys | < 4.5:1 |

The dark reader theme passes on chapter eyebrows; light does not. The
paragraph numbers fail everywhere — they are content (jump targets,
citations), not decoration, so 1.4.3 applies.

### Moderate — no landmarks (axe `landmark-one-main`, `region`)

No `<main>` (or any landmark) wraps the document body: 307 nodes outside
landmarks on LS, 127 on GeS, plus the settings-panel rows. A screen-reader
user gets no "skip to main content" affordance. Cheapest fix: wrap the body
column in `<main>`, mark the corner controls as `<nav aria-label>` /
`role="toolbar"`.

### Moderate — heading outline is inverted

The document title (`.doc-title`) is a `div`, not a heading. The page's
reading order therefore opens at `<h5>` (preamble sub-headings), chapters are
`<h2>`, chapter titles `<h3>`, sections `<h4>` — and the only `<h1>`s on the
page are the appendix titles at the very end ("A prayer for our earth").
axe flags one skip in the drawer TOC (`heading-order`), but the real issue is
the whole outline: heading-nav (the primary SR navigation idiom) is
incoherent. Suggested shape: `h1` doc title, `h2` chapter, `h3` chapter
title/section, `h4` sub-heading, appendices as `h2`.

### Keyboard flow

- **Escape does not close the drawer.** Open via Enter on the toggle works
  and `aria-expanded` updates, but there's no keyboard close short of
  re-tabbing to the toggle.
- **Focus is not managed into the drawer.** After opening, focus stays on the
  toggle; the drawer's first focusable element is tab stop **188 of 299**
  (it sits at the end of the DOM), so a keyboard user must traverse half the
  document's links to reach the panel they just opened.
- **Footnote refs don't move focus.** Enter on an in-text ref opens the
  drawer and selects the note visually, but focus stays in the body, so an
  SR user hears nothing happen.
- **Scroll indicator is mouse-only.** `#ch-indicator` is a `<nav>` with zero
  focusable children and no `aria-label` — jump-anywhere navigation is
  unreachable by keyboard, and it registers as an anonymous empty landmark.
  The drawer TOC is a working keyboard alternative, which mitigates but
  doesn't excuse the unlabelled landmark; `aria-hidden="true"` (plus keeping
  it out of the landmark tree) may be the honest minimum.
- **Info and settings panels expose no state.** Unlike the drawer toggle,
  `#action-info` / `#action-prefs` have no `aria-expanded`; the panels have
  no `role`, no label, and focus is unmanaged.

### Settings panel semantics

- The three text-size buttons all have accessible name **"A"** —
  indistinguishable to AT. Needs `aria-label` ("Small text" / …).
- Active choice (theme, size, font) is conveyed by an `active` class only —
  colour-only affordance, no `aria-pressed`/`aria-checked`. The bookmark
  toggles already model the right pattern in this codebase.

### Minor

- In-text footnote refs announce as bare "1", "2" — `aria-label="Footnote 1"`
  (or a visually-hidden prefix) would give them a name worth hearing.
- No live regions anywhere (`aria-live` count: 0) — bookmark add/remove and
  theme changes produce no announcement.

## Not covered

EPUB/PDF outputs; screen-reader smoke test with real VoiceOver; touch-target
sizing; `prefers-reduced-motion` behaviour of the drawer/indicator animations.
